# "触发生成"按钮的作用说明

## 概述

在选品智能体页面，每个商品都有一个 **"触发生成"** 按钮（带有闪电图标），用于启动该商品的**自动化上架工作流**。

## 核心作用

一键触发从"已选品"到"上架销售"的**全链路自动化处理流程**。

## 工作流说明

### 触发的工作流：单品上架流程

**模板ID**: `single_product_publish`

**流程说明**: 选品 → 图片 → Listing → 定价 → 上架

### 7个处理步骤

| 步骤 | 名称 | 智能体 | 说明 | 是否必需 |
|------|------|--------|------|---------|
| 1 | 选品分析 | product-selection | AI分析市场潜力 | ✅ 必需 |
| 2 | 图片处理 | image-design | 生成主图、背景替换、翻译 | ✅ 必需 |
| 3 | Listing优化 | listing-optimization | 生成标题、描述、关键词 | ✅ 必需 |
| 4 | 合规校验 | compliance-checker | 检查敏感词、禁售品类 | ✅ 必需 |
| 5 | 智能定价 | pricing-engine | 计算成本、利润、定价 | ✅ 必需 |
| 6 | 上架发布 | publish-agent | 发布到平台 | ✅ 必需 |
| 7 | 广告创建 | advertising | 自动创建广告计划 | ⚪ 可选 |

## 详细处理流程

### 步骤1：选品分析 ✅

**执行内容**：
- 调用豆包大模型分析商品市场潜力
- 评估竞争程度和需求量
- 生成市场分析报告

**输入**：
- 商品名称
- 商品类目

**输出**：
```json
{
  "analysis": "商品在TikTok印尼站具有良好市场潜力，年轻用户群体对该类商品需求旺盛，预计月销量500-1000件。"
}
```

---

### 步骤2：图片处理 ✅

**执行内容**：
- 生成商品主图（800x800）
- 背景替换为白底或场景图
- 图片文字翻译（中文→英文）
- 图片合规检查

**输入**：
- 商品名称
- 商品类目

**输出**：
```json
{
  "image_id": "IMG1775237975910",
  "type": "main",
  "url": "https://placehold.co/800x800?text=...",
  "status": "done"
}
```

---

### 步骤3：Listing优化 ✅

**执行内容**：
- 生成吸引人的商品标题（中英文）
- 撰写商品描述
- 提炼5点卖点（Bullet Points）
- 生成SEO关键词
- 计算SEO得分

**输入**：
- 商品中英文名称
- 商品类目

**输出**：
```json
{
  "title": "Premium Quality Silicone Heat-Resistant Bowl with Lid",
  "description": "High quality silicone bowl with lid. Best choice for you.",
  "bullet_points": [
    "Premium Quality",
    "Fast Shipping",
    "Best Price",
    "Satisfaction Guaranteed"
  ],
  "keywords": ["best", "quality", "sale", "hot"],
  "seo_score": 85
}
```

---

### 步骤4：合规校验 ✅

**执行内容**：
- 检查敏感词（医疗、治疗、最佳、第一等）
- 检查禁售品类
- 检查品牌授权问题
- 检查价格异常

**输入**：
- 商品名称
- 商品描述

**输出**：
```json
{
  "passed": true,
  "issues": []
}
```

**失败处理**：
- 必需步骤，如果校验失败则终止工作流
- 显示错误信息，告知用户需要修改

---

### 步骤5：智能定价 ✅

**执行内容**：
- 计算总成本（商品+国内运费+头程运费）
- 计算平台佣金（15%）
- 计算预期利润
- 生成建议售价

**输入**：
- 商品成本
- 总成本
- 利润率要求（默认30%）

**输出**：
```json
{
  "suggested_price": 36,
  "profit_margin": 0.3,
  "cost_breakdown": {
    "product_cost": 23.2,
    "platform_fee": 5.4,
    "shipping": 10,
    "profit": 10.8
  }
}
```

---

### 步骤6：上架发布 ✅

**执行内容**：
- 生成平台Listing
- 提交到TikTok Shop
- 设置库存数量
- 设置运费模板

**输入**：
- 商品ID
- 平台（tiktok/amazon）
- 站点（id/my/th/vn/ph/sg）

**输出**：
```json
{
  "listing_id": "LST1775237975910",
  "platform": "tiktok",
  "region": "id",
  "status": "listed",
  "listed_at": "2026-04-03 18:00:00"
}
```

---

### 步骤7：广告创建 ⚪

**执行内容**：
- 自动创建广告计划
- 设置预算（默认$100/天）
- 设置投放商品
- 优化广告素材

**输入**：
- 商品ID
- 商品名称
- 平台

**输出**：
```json
{
  "ad_id": "AD1775237975910",
  "name": "硅胶防烫带盖泡面碗套装-自动推广",
  "budget": 100,
  "status": "active"
}
```

**说明**：
- 非必需步骤
- 如果失败不影响上架流程
- 可以后续手动创建

## 使用场景

### 场景1：快速上架单个商品

1. 在选品智能体页面查看选品结果
2. 找到要上架的商品
3. 点击"触发生成"按钮
4. 系统自动执行7个步骤
5. 完成后跳转到工作流页面查看进度
6. 商品状态变为"待上架" → "已上架"

### 场景2：批量处理多个商品

1. 选品成功后，生成多个商品
2. 为每个商品点击"触发生成"
3. 系统并行执行工作流
4. 在工作流页面统一监控进度
5. 批量上架所有商品

---

## 与"开始处理"的区别

| 功能 | 触发生成 | 开始处理 |
|------|---------|---------|
| 位置 | 选品智能体页面 | 商品管理页面 |
| 作用 | 启动完整上架工作流 | 仅启动图片处理 |
| 包含步骤 | 7个步骤（选品→上架） | 1个步骤（图片处理） |
| 适用场景 | 快速全链路上架 | 单独处理图片 |
| 结果 | 商品上架到平台 | 图片处理完成 |

**推荐流程**：
```
选品完成 → 点击"触发生成" → 全自动上架 → 商品开始销售
```

## 工作流状态

### 状态流转

```
pending（待执行）
    ↓
running（运行中）
    ↓
    ├── completed（完成）✅
    ├── failed（失败）❌
    └── cancelled（取消）⏹️
```

### 步骤状态

```
pending（待执行）
    ↓
running（执行中）
    ↓
    ├── completed（完成）✅
    ├── failed（失败）❌
    └── skipped（跳过）⏭️
```

## 实时监控

### 工作流页面

点击"触发生成"后，会自动跳转到工作流页面，可以实时查看：

1. **工作流列表**
   - 显示所有运行中的工作流
   - 显示当前执行步骤
   - 显示执行进度

2. **步骤详情**
   - 每个步骤的执行状态
   - 执行结果
   - 执行时间

3. **进度条**
   - 总体进度百分比
   - 当前步骤指示

---

## 错误处理

### 必需步骤失败

**行为**：
- 工作流状态变为"failed"
- 终止后续步骤执行
- 显示错误信息

**示例**：
```
步骤: 合规校验
错误: 合规校验失败: 包含敏感词: 医疗
操作: 停止工作流，提示用户修改商品名称
```

### 可选步骤失败

**行为**：
- 步骤状态变为"skipped"
- 继续执行后续步骤
- 工作流正常完成

**示例**：
```
步骤: 广告创建
错误: 广告API调用失败
操作: 跳过此步骤，继续上架流程
结果: 商品成功上架，但广告未创建
```

## 技术实现

### API调用

```typescript
// 选品智能体页面调用
fetch('/api/v1/workflow/execute', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    template_id: 'single_product_publish',
    user_id: 'web_user',
    params: {
      product_name: product.name,
      product_id: product.id,
      category: product.category,
      platform: 'tiktok',
      region: 'id',
    }
  })
})
```

### 异步执行

工作流采用异步执行方式：

1. **立即返回**：API调用后立即返回工作流ID
2. **后台执行**：工作流在后台异步执行
3. **进度查询**：通过工作流页面实时查询进度
4. **状态更新**：每个步骤完成后更新状态

### 数据存储

- 工作流数据保存在全局存储
- 商品状态随步骤执行而更新
- 执行结果记录在工作流中

## 使用建议

### 何时使用"触发生成"

✅ **推荐使用**：
- 选品成功后立即使用
- 需要快速上架商品时
- 希望全自动化处理时
- 批量上架多个商品时

❌ **不推荐使用**：
- 只想处理图片时（使用"开始处理"）
- 需要手动调整时
- 测试阶段

### 最佳实践

1. **选品后立即触发**：不要让商品在"已选品"状态停留太久
2. **监控工作流进度**：及时发现问题并处理
3. **检查上架结果**：确认商品成功上架
4. **优化Listing**：上架后根据数据优化标题和描述

## 总结

**"触发生成"按钮的核心价值**：

1. **一键全链路**：从选品到上架，一键完成所有步骤
2. **自动化处理**：无需人工干预，系统自动处理
3. **AI驱动**：每个步骤都由AI智能体执行
4. **快速上架**：大大缩短上架周期
5. **批量处理**：支持批量处理多个商品

**适用场景**：
- 选品成功后快速上架
- 批量处理多个商品
- 全自动化运营

**不适用场景**：
- 只想处理图片
- 需要手动调整细节
- 测试阶段
